# AI 助手当前路线图

**日期**: 2026-05-01
**状态**: 当前活文档

## 定位

AI 页面已经不再只是“伴读”页面，而是 CiteBox 的 AI 助手与研究调度中心。它的核心职责是把用户的自然语言请求路由到应用内部已有能力，包括本地文献库全文搜索、外部学术检索、文献阅读/对比和图文检索。

旧的 `docs/superpowers/specs/*` 和 `docs/superpowers/plans/*` 保留为归档设计与实施记录。后续 AI 助手方向的优先级以本文档为准。

## 已完成基础

- `/ai` 已经是服务端持久化会话，不再是浏览器内存里的单篇伴读。
- 已有会话列表、重命名、删除、搜索、多文献 pin、`@` 文献选择、自动标题、导出和上下文预算。
- 已有 AI orchestrator/tool 架构，覆盖全库搜索、外部搜索、文献阅读/对比和图文检索。
- 已有 process strip、result cards、citation 恢复和 run/tool/card 持久化。
- 内部文献搜索已经支持全文扫描，并可走轻量 Master/Sub-Agent 风格的 planner/classifier。
- 外部搜索复用 Semantic Scholar 能力。
- 图文检索支持直接搜图，也支持通过全文候选文献 fallback。
- 当前路线明确禁止 embedding 和 vector database。

## 当前优先级

### P0: 网页真实可用性验收

目标是确认 AI 助手四类核心请求在浏览器中真实可用，而不是只在后端测试里成立。

- [ ] 内部全文搜索：例如“查找包括 ChIP-seq 数据的文章”，应显示规划、全文扫描、Sub-Agent 判定、命中文献卡片和证据片段。
- [ ] 外部搜索：例如“查一下外部有没有 single-cell ATAC 综述”，应独立触发外部检索，失败时给出可解释状态。
- [ ] 文献阅读/对比：选择 1-2 篇文献后提问，应读取选中文献全文并返回对比结果。
- [ ] 图文检索：例如“在文献库中找一张 ChIP-seq 相关的图”，应返回图卡、图注和证据来源；直接搜不到时使用全文候选 fallback。
- [ ] 重新打开历史会话后，process strip、result cards、citation 和折叠状态应能合理恢复。

验收方式:

- 使用已经运行的 `make dev` 页面做手工验证。
- 必要时配合 Playwright 截图检查页面空白态、思考态、卡片折叠、证据高亮和长对话滚动条。
- 每次发现问题，优先补最小回归测试或前端语法检查，再修代码。

### P1: 调度过程可观察

目标是让用户能理解“AI 正在查什么、为什么命中、在哪里失败”，但不把页面变成复杂任务中心。

- [ ] process strip 继续保持紧凑，但阶段名称需要稳定，例如 `Master规划`、`全文扫描`、`Sub-Agent判定`、`命中`、`生成回答`。
- [ ] 内部搜索需要显示候选数量、判定数量、命中数量。
- [ ] 外部搜索需要显示搜索源、返回数量和失败原因。
- [ ] 图文检索需要显示是直接命中图，还是从全文候选文献 fallback。
- [ ] 失败时不要只返回“证据不足”，而要说明是没有命中、检索失败、模型判定失败，还是上下文不足。

### P2: 模型场景绑定

目标是让强模型做规划与综合，便宜模型做高并发判定，从配置上明确 Master/Sub-Agent 的职责。

- [ ] settings 中明确 Master 模型和 Sub-Agent 模型的绑定关系。
- [ ] Master 默认适合使用强推理模型，例如 GPT-5.5 thinking/xhigh 或同等级模型。
- [ ] Sub-Agent 默认适合使用便宜并发模型，例如 DeepSeek Flash。
- [ ] 支持 provider-specific 参数，例如 DeepSeek `thinking`、`reasoning_effort`，以及 OpenAI Responses 不支持 `temperature` 的模型差异。
- [ ] 模型检查应能提示具体 unsupported parameter，而不是让用户猜。

### P3: AI 页面体验收口

目标是让 AI 页面继续像传统对话页面，而不是工具堆叠页。

- [ ] 左侧会话区、主对话区和结果卡片的视觉层级保持一致。
- [ ] 删除确认继续使用应用内原生 modal，不使用浏览器 prompt/confirm。
- [ ] `@` 文件选择框保持向上弹出，适配底部输入框。
- [ ] 输入框自动增高，不允许手动拖拽破坏布局。
- [ ] 黑色、黄色和蓝色主题下长对话滚动条都应协调。
- [ ] 结果卡片默认折叠，证据片段支持关键词高亮。

## 暂不做

- 不做 embedding。
- 不做 vector database。
- 不做长时间后台任务中心。
- 不做复杂多 Agent 面板。
- 不做移动端重设计，除非当前桌面布局已经稳定。

## 下一步执行建议

1. 先做 P0 的浏览器验收，把真实不可用的问题修完。
2. 再补 P1 的可观察性，让用户能看懂 Master/Sub-Agent 的调度过程。
3. 然后做 P2 的模型场景绑定，把强模型和便宜模型的职责固定下来。
4. 最后按 P3 收口 UI 细节，避免功能增强把对话页变成杂乱面板。
